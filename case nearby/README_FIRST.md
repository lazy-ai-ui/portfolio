Работа над кейсом Nearby
Контекст проекта
Nearby — приложение для аренды вещей рядом с пользователем (примерно 5–30+ минут). 
Цель кейса — показать не только финальные экраны, но и процесс принятия решений: от проблемы и исследования до продуктовых решений и их обоснования.
Важно: это не презентация UI. Каждый блок должен отвечать на вопрос:
"Почему это решение появилось и какую проблему пользователя оно закрывает?"
Структура проекта
Все материалы находятся в папке:
Case Nearby
Перед началом работы:
Изучи все .md файлы внутри папки.
Изучи структуру папок.
Составь единый структурный документ:
Nearby_Case_Context.md
Он должен стать главным источником контекста для дальнейшей работы.
В нем должны быть:
краткое описание продукта
проблема
целевая аудитория
ключевые инсайты
исследование
гипотезы
продуктовые решения
структура кейса
правила визуальной подачи
терминология проекта
После создания единого файла старые .md можно удалить, если они полностью перенесены.
Источники контента
1. Case source
Папка:
case source
Здесь находятся тексты для блоков кейса.
Формат:
01.md
02.md
...
11.md
Используй их как источник содержания.
Задача:
сохранить смысл автора
убрать повторения
адаптировать под формат портфолио
сделать текст живым и понятным
не превращать его в сухую документацию
При сокращении нельзя терять:
проблему
ход мысли
причину решения
компромиссы
ограничения
2. Layout flow
Папка:
layout flow
Внутри находятся флоу и экраны.
Используй их после анализа текста.
Важно:
Не просто показывать экран.
Каждый показанный экран должен отвечать:
какую проблему решает?
почему именно такая структура?
какое поведение пользователя учитывает?
Если экран нельзя объяснить через продуктовую логику — предложи убрать его.
3. References
Папка:
references
Это визуальные референсы.
Используй их:
для поиска визуального языка
структуры блоков
способов подачи информации
Это НЕ шаблон.
Не копируй структуру автоматически.
Если есть идея лучше — предлагай.
Правила сборки кейса
При создании каждого блока думай как Product Designer:
Не:
"Вот экран, который я сделал"

А:
"Была проблема → я исследовал → нашёл закономерность → принял решение → получил такой результат"

Формат работы
Перед созданием блока:
Определи цель блока.
Определи главный месседж.
Предложи несколько вариантов визуальной подачи.
Объясни плюсы и минусы.
После выбора собирай финальную версию.
Визуальные ограничения
Сохраняем единый стиль портфолио:
чистый минимализм
акцент на продуктовой логике
много воздуха
сильная типографика
минимум декоративных элементов
Но:
каждый кейс может иметь свой сторителлинг.
Не использовать один шаблон для всех проектов.
Роль агента
Ты работаешь не как верстальщик.
Ты — дизайн-партнёр.
Твоя задача:
замечать слабые места истории
задавать вопросы
предлагать улучшения
находить несостыковки
помогать сделать кейс сильнее для собеседования Product Designer
Если решение выглядит сомнительно — говори об этом.
