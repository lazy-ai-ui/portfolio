# Портфолио Фирдавса — передача в Claude Code

Этот файл — весь контекст проекта одним куском. Вставь его целиком первым сообщением в Claude Code, приложи `main-latest.html`, `case-latest.html` и `dashboard-original.png`, и можно продолжать работу с того же места.

## Что это

Портфолио продуктового дизайнера. Сейчас существует как отдельные HTML-файлы (собирались в чате Claude.ai, каждая правка — новый файл). Пора превратить это в нормальный проект с гитом и деплоем.

Живой сайт сейчас: собран во Framer, лежит на `designbyfir.framer.website`. Новую версию строим с нуля на HTML/CSS/JS (или React — на усмотрение Claude Code), потому что нужен полный контроль над кастомной анимацией на канвасе, которую Framer не потянет.

--surface: #FFFFFF;      /* карточки на светлом */

--on-dark-3: rgba(237,235,232,.32);
--accent: #E4573A;        /* единственный акцентный цвет, использовать точечно */

--display: "Geist", "Inter", system-ui, sans-serif;  /* когда-то был Cormorant (serif), отказались — см. ниже */
--body: "Geist", "Inter", system-ui, sans-serif;

Шкала отступов: 4px-база (8/16/24/40/64/104/160).

**Важно про шрифты.** Три семейства подключены через Google Fonts CDN — это блокирует отрисовку и через это отменили сериф Cormorant в пользу Geist. Первая задача для Claude Code — забрать файлы шрифтов локально (только кириллица + латиница, без лишних наборов), `font-display: swap`, woff2.

## Голос и принципы

- Русский язык сейчас, английская версия — позже (после первого коммерческого опыта). Тексты пишутся с заделом на будущий i18n — не хардкодить в разметку, держать в объекте с ключами, когда дойдём до реального контента.
- Тон текста: конкретика вместо общих фраз о себе. Не «люблю глубоко погружаться», а «переработал главный экран так, чтобы он отвечал на вопрос всё ли хорошо».
- Формулировки — от боли пользователя, а не от структуры системы.
- Никаких выдуманных метрик. Если цифры нет — либо не пишем, либо помечаем как гипотезу с явной оговоркой (см. паттерн caveat в case-latest.html).
- Один акцентный цвет (`--accent`), используется точечно: точка статуса, коралловая карточка в хиро-фигуре, хайлайты в тексте. Не путать с семантическими цветами внутри скриншотов продукта (там уже есть красный/зелёный/жёлтый — свой акцентный цвет не должен с ними спорить).

## Визуальный язык — «частицы»

Сквозной приём сайта: квадратные частицы (canvas 2D), которые левитируют хаотично и складываются в структуру при взаимодействии. Метафора: хаос становится порядком — ровно то, чем занимается дизайнер.

Правило, которое установили в процессе: **повторяем словарь (квадрат, шаг сетки, коралловый акцент), а не анимацию**. Движение — только там, где оно что-то значит. Максимум 2-3 анимированных места на весь сайт, остальное — статичные вариации того же языка (пунктирная строка-разделитель из квадратиков, статичная россыпь в слоте "не собрано").

Реализовано в `main-latest.html`:
- Хиро: частицы левитируют, при наведении/тапе собираются в один из трёх случайных макетов интерфейса (дашборд / телефон / планшет). Логика — весь `<script>` в конце файла, читай комментарии, там разобрано по функциям (`buildLayout`, `scatter`, `frame`).
- Анимация остановлена, когда блок не виден (IntersectionObserver) и когда вкладка в фоне — иначе сажает батарею без пользы.
- `prefers-reduced-motion` — везде уважается, статичный кадр вместо анимации.

## Структура главной (main-latest.html)

1. Navbar — плавающая пилюля, скрывается при скролле вниз, появляется при скролле вверх и у самого верха страницы.
2. Hero — тёмный блок, частицы по центру, факты о себе слева (с фото-плейсхолдером и статусом "открыт к работе" — коралловая пульсирующая точка), фраза о подходе справа.
3. Projects — чередующаяся сетка (текст/медиа meняются местами, как у adamreznik.com). Обложка кейса — "веер" из двух карточек (светлая/тёмная тема, по мотивам переключателя темы в самом продукте RackTables), расходится по ховеру. Один проект живой (RackTables), второй — заглушка "не собрано" с той же россыпью частиц, но статичной.
4. About — фото крупное (второе, живое, не то что в хиро), три абзаца текста-заглушки с пометками что в них должно быть, мини-список инструментов/методов/языков.
5. Contact — тёмный блок (рифмуется с хиро), заголовок, ссылки (Telegram/Email), футер.

Разделители между секциями — не линия, а пунктирная строка из квадратиков (`.rule`), тот же визуальный язык.

## Структура кейса (case-latest.html)

Каркас — CPPPR (Context, Problem, Process, Solution, Result), но пропорция сознательно смещена: у автора в исходном кейсе было 2/3 исследования и 1/3 решения, тут наоборот.

1. Заголовок + плашки (тестовое для Яндекса / Gravity UI / год) + блок "задача / что получилось" в две колонки + мета (роль, срок — 7 дней, что делал, инструменты).
2. **Обзор решения** — сразу картинки и три карточки с проверяемыми фактами (12→1 экран, 3 клика на разрешение конфликта IP, 2 интервью). Приём подсмотрен у рефа-сеньора (Edu Cabellos), но без выдуманных метрик — внизу честная сноска, что цифры про решение, а не про измеренный эффект.
3. **Процесс** — три фазы вместо восьми пунктов чек-листом, который был в исходнике.
4. **Проблемы** — ЗАГЛУШКА, следующий шаг. Сюда идут 4 инсайта из интервью (полный текст кейса уже поднят из фетча designbyfir.framer.website/case — см. в истории переписки, если он не сохранился отдельно, попроси у Фирдавса).
5. **Решение** — готово частично. Аннотированный дашборд с 4 кликабельными хотспотами (позиции в `%`, не в px — данные в массиве `DATA` в скрипте, привязаны к описанному в интервью барьеру). Плюс блок "что это даёт" с фактом + сворачиваемая оговорка "что ещё стоит проверить" (паттерн для честности вместо слова "гипотеза").
6. **Итог** — ЗАГЛУШКА.
7. Нижняя плавающая навигация по разделам (пилюля, подсвечивает активный раздел через IntersectionObserver, скроллится горизонтально на мобилке).

## Известные технические долги

- Картинка дашборда сейчас зашита как base64 (~200KB в разметке) — это временно, для превью в чате. **Обязательно вынести в `/assets`, пережать в webp, лениво грузить.**
- Скриншоты продукта в оригинале — до 5760px шириной, это дорого. Сжимать вход.
- Три Google Fonts блокируют отрисовку — переносить локально (см. выше).
- Веер тем в карточке проекта — тоже сейчас с плейсхолдерами вместо реальных скриншотов темы.

## Проверено и работает

- В браузере через реальный деплой (Netlify) — Safari, скорость, анимация, тёмная тема системы — всё ок.
- Известный false positive: встроенные просмотрщики (Telegram in-app browser, Quick Look) могут не выполнять JS и принудительно перекрашивать в тёмную схему — это баг просмотрщика, не сайта. `color-scheme: light only` уже стоит.

## Первая задача для Claude Code

1. Собрать нормальную структуру проекта (см. предложение по файлам ниже).

4. Настроить гит + деплой (Vercel/Cloudflare Pages/GitHub Pages — на выбор, раньше пользовались Netlify Drop вручную).
5. Дальше — по ходу: доделать разделы "Проблемы" и "Итог" в кейсе, добавить реальные фото и скриншоты, второй кейс.
